# Architecture and design decisions

## Native Rust ownership

Optional host-owned session steering resolves bounded global/project/local
defaults and CLI selection with persistent base/added modes. Literal context and
mode guidance never evaluates templates or grants authority. MCP catalogs and
dispatch share exact exclusions; real catalog changes emit bounded notifications
through stdio or finite HTTP SSE. Versioned host bindings, recomputed effective
modes and CAS updates preserve stale/forgery/concurrency refusal. The legacy
default agent profile retains its original serialized identities.
See [the native contract](../native/docs/session-steering.md).

Explicit REPL API exclusions additionally bind per-cell discovery and every
host callback to current session policy. Qualified private bridges preserve
declaration/context origins; cached callables and the generic native helper
cannot bypass selection. Ordinary tool adapters use a separate host-owned
origin. Empty API fields preserve preceding serialized identities and results.

The explicit Git compiler-affected query releases the checked report read view
before trusted host compiler execution and revalidates original pins afterward.
Independent snapshot/project contexts retain actual checker declarations, exact
UTF-8 quotes, constructor/tag/overload bindings and type-based instance/constructor
targets. Construct-result classes stay separate from constructor bodies and values.
Possible targets pair with exact original invocation roles/proofs. A separate
constructor-value edge targets each candidate class, so shared
inherited bodies do not hide class-only changes from incoming traversal.
Native checks endpoints, owners, source ranges and capacities; original graphs/reports remain
unchanged. Host/module/worker hashes, library/configuration pins and visible
coverage stay separate from independent compiler correctness or execution proof.
Source-observed generic instances retain exact type/argument/syntax witnesses,
with separate union branches and complete intersection types. Candidate witness
IDs are source/context scoped; display strings never stand in for type identity.
Property slot references, applicable getter/setter effects and direct function
initializer ownership are distinct from resolved invocation signatures. Candidate
accesses pair exact original slot/proof/modes and actual class/type witnesses;
syntactic optional reads and logical conditional writes remain separate. Native
checks source containment and pairings without inferring returned function values
or runtime property state.
An independently derived incoming walk can additionally step outward through
exact override/implementation bindings at zero incoming distance. Separate
contract proofs retain direction/parallel source evidence and distinguish an
unchanged supertype from an original seed. Distance relaxation preserves shorter
contract paths without discarding longer original proofs; this is conservative
source-contract impact and never invents a generic instance or invocation.
See [the contract](../native/docs/git-compiler-affected.md).

The separate live Explorer owns a fixed host Engine/capture selection and cached
immutable HTML. Fragment bootstrap capability becomes an authenticated header;
Host/Origin, HTTP framing, closed JSON and output/deadline bounds are independent.
Public bootstrap/refusals expose no source binding. Manual capture additionally
requires a host grant and exact view revision/snapshot, while GET only reloads
the cached view. A short admission deadline prevents speculative idle sockets
from consuming the capture budget. Source export completes before the cached
view swaps; independently persisted captures are not rolled back on export error.
An opaque sandboxed iframe retains static source CSP and no parent DOM access.
See [the live contract](../native/docs/explorer.md#authenticated-local-live-workflow).

The explicit source-bearing offline Explorer reuses canonical Store/snapshot/
graph/captured-path/source-hash/UTF-8/range admission. It admits the complete
source byte set before blob reads and bounds serialization, escaping and the
final output. Borrowed source bindings retain original bytes without JSON Value
copies. A separate presentation adds Code/Context/Outline and exact quotes while
the old metadata-only and document template stays byte-identical. Source text
never becomes markup or authority; the browser performs no network/project
execution or freshness check. See [the contract](../native/docs/explorer.md).

Classic compiler-selected body expansion preserves predicate/assertion caller
flow through an inert original signature and fixed relay of the computed result.
Native derives explicit source targets, restricts generated references to ordinary
captured lexical bindings and matches separate exports by declaration identity.
Inferred predicates retain the trusted compiler boundary; complete surviving
observations still agree. Known dense argument indices retain element types and
genuine undefined. Original evaluation and independent write gates remain. See
the [predicate contract](../native/docs/compiler-inline-predicates.md).

The optional Claude SessionStart adapter owns an entire external settings file,
leaving foreign hook arrays alone. Literal native argv carries the original
physical bindings. A bounded unique-key stdin callback checks the current
installed receipt and source/policy/executable identities before emitting only
advisory source-scope metadata, with freshness explicitly not checked. No Store,
transcript read, model, permission decision or initial user message is created.
Existing guarded apply/recovery and old profile identities remain intact. See
the [hook contract](../native/docs/claude-session-hooks.md).

Explicit JSON MCP clients share guarded host installation through closed typed
adapter bindings and distinct profile identities. Scoped strict-JSON ownership
tracks exact server member bytes and created shells; configuration remains
separate from source and private journal roots. Client launches are literal
host-selected argv, with no approval/model defaults. The same canonical edits
and physical bindings govern ordinary apply and interrupted recovery. See the
[JSON client contract](native-json-hosts.md).

Optional source-category graph analysis uses an explicit bounded mapping from
original resolution strings to declared report categories. Relation weights,
ambiguity scaling and node display filters belong to that derived policy;
original directed/parallel observations and source bindings remain authoritative.
Runtime-family/source-kind surprise components have explicit reasons. Policy
reports and checked View registrations use separate producers and exact replay.
Canonical policy retention reconstructs source/options/history read-only and
compares exact serialized bytes; signed zero cannot pass by Value equality. The
pinned JSON parser preserves finite float roundtrips. The absent-policy branch
preserves released options/artifact identities. See
[the policy contract](../native/docs/source-category-policy.md).

Explicit neighbor-majority-v1 community analysis separately selects an
undirected positive-weight projection, unique-neighbor hub degree/voting,
stranded-node holdout and two bounded split stages. Source-order ties avoid
snapshot-hash churn. Its canonical/View producers and exact retention replay
bind the selected options; no split or final maximum-size guarantee is invented.
Absent community options preserve both older report families. See the
[community contract](../native/docs/community-policy.md).

Captured owner changes separately compare the full saved base/head path union,
including unchanged file bodies, through the checked impact/area transaction and
shared finite rule evaluator. Exact original source/token evidence and the parent
remain unchanged. Candidate changes and winning-line evidence changes differ from
source-body changes; missing rules stay indeterminate. New body/match/output
bounds admit complete results without writes, Git, network or model execution.
This grants no identity, permission or actual review authority. See the
[owner-change contract](../native/docs/git-owner-changes.md).

Classic function-body inlining uses independent original-byte statement frames
through the optional `inlineCompiler` profile. Arguments evaluate before separate
parameter/body scopes; checked defaults, rest/patterns and labelled returns keep
finite source and compiler binding correspondence. Normal completion clears a
return cancelled by finally control flow. Every replacement is reconstructed
natively before ordinary planning; static observations do not attest general
runtime equivalence. Function-owned var hoists retain original-position
initializers, shared loop storage and separate parameter/catch assignment roles.
Explicit annotations and fixed primitive hints retain admitted compiler types.
Nonprimitive var storage additionally uses fixed typeof syntax with fresh carriers
inferred from original declarations or loop heads at their lexical sites. The fixed
pure-false void guard prevents copied expressions and reads from executing without
suppressing enabled compiler diagnostics. Native byte reconstruction, raw binding/
type coverage and source-ordered composition preserve keys, labels and control slots.
A fixed runtime-true guard retains the original body block and enabled reachability
checks; normal completion clears cancelled returns outside it, with a label only
for actual outer returns. Inferred result types use fixed typeof syntax over an inert
result carrier from a
never-executed source-function call with already evaluated fresh argument temps.
Attached JSDoc templates, literal inference and free bindings retain checked scope.
Empty declaration statements protect neighboring annotation/typedef ownership.
Caller JSDoc moves once with its original lexical declaration in the same
scope, after generated statements; the native parser derives the widened edit
extent and exact source correspondence. Copied callee function tags stay in one
contract comment so template/parameter/return binders remain together. Context-sensitive arguments use a fixed pure rest collector with an inert
source-derived callable signature. Original arguments run once before existing
parameter/default/body lowering; raw dense-array indexing avoids iterator hooks.
Bounded original documentation pieces retain compiler type authority and native
byte/binding checks. Simple literal/identifier arguments keep direct bindings and
generic scalar inference. Both recipes retain exact surviving caller/argument
types and independent application gates. Original TypeScript return annotations
also contextually type result storage, with
a fixed undefined alternative for normal completion. Fixed void-comma return
barriers retain anonymous function/class runtime names. Exact source annotation
and barrier reconstruction precede binding/type checks. Original/fixed result
assertions use a fixed unknown intermediate. Native
comment/BOM ownership, fresh names and copied binding/type checks remain mandatory.
Further return/parameter/annotation contexts and invocation/expression forms remain open. See [compiler inlining](../native/docs/compiler-inline.md).

The compiler-move repair stage reconstructs direct named reexport partitions and
fresh local import aliases from original/current immutable source anchors.
Native original-byte pieces compose staged changes while preserving untouched
regions. Shorthand property keys and value bindings have separate correspondence
roles. Repair steps share the compiler's operation budget and retain final
source/binding/API/verification gates. Captured omitted imports and source-owned
free dependencies have independent origin, module and insertion checks. Required
source exports are disclosed; computed `__proto__` keys preserve own-property
semantics. Unsupported substitutions still refuse. See [compiler moves](../native/docs/compiler-move.md).

The separate optional `moveCompiler` host profile uses actual TypeScript 5.8.3
Move to file output over immutable captured modules. Native syntax/binding,
import/export coverage and result-byte checks precede ordinary guarded plans.
Graph-absent variable/namespace selection has explicit AST provenance, with no
invented graph entity. Original BOM normalization is independently reproduced;
unsupported compiler effects refuse. See [compiler moves](../native/docs/compiler-move.md).

The optional session `inlineCompiler` profile binds an explicitly trusted host
Node executable and TypeScript 5.8.3 module. Rust checks captured declaration and
reference spans, copied initializer syntax, exact statement/comma removal bundles
and the final bytes before one guarded plan. The compiler uses immutable virtual
source, checks free bindings and before/after diagnostics, and loads no repository
plugins or modules. Existing LSP routes, analyzer identities and independent
application/recovery gates remain. See [compiler inlining](../native/docs/compiler-inline.md).

`meaning_identity` consumes existing joint native Meaning source/receipt replay,
then computes a fixed bounded normalization/MinHash/LSH/Jaro candidate set. One
explicit host-provider attempt uses a separate ledger/job/payload contract and
immutable raw response. Complete per-pair source-supported model decisions admit
only positive cliques; sparse transitive chains, conflicts or missing coverage
refuse publication while preserving bound billing. The private frozen quotient
retains every original concept, directed observation and ordered role slot.
Node/degree/directed-trace consumers share the existing join query engine behind
a separate checked capability and schema. No original claim is rewritten, and
neither labels nor model decisions establish semantic truth or execution. Typed
retention bounds new job/source metadata before legacy materialization and follows
only validated roots of new jobs/artifacts. See [semantic identity](../native/docs/meaning-identity.md).

`knowledge::feedback::semantic_transcript` owns a separate imported UTF-8 source
space and explicit single-attempt host-provider contract. Atomic ledger/job/input
registration precedes dispatch; original bound bills/replies remain durable before
domain rejection, unknown sends retain reservations and no job grants another send.
Provider-free replay checks original transcript/header/CAS, payload, response,
ledger and exact reconstructed candidates. Private immutable checked exports survive
Store loss. Typed retention validates all job states before recognizing their roots.
Candidates retain parallel observations and ordered quotes, create no outcome events
and establish no semantic truth or observed execution. Source-write claims apply
to the native parent; trusted providers have no claimed filesystem isolation. See
[semantic transcript candidates](../native/docs/semantic-transcript-candidates.md).

conferring no execution authority. See [App history](../native/docs/app-history-integration.md).

`mixed_view::provider` and the separate `mixed-meaning` CLI use a fixed typed

## Boundaries

```text
CLI / MCP stdio / read-only local explorer / library
                        |
                 CodeIntelligence.invoke
          validation, scope, shared deadline, budget
                        |
    Snapshot/CAS -> native analyzers -> canonical evidence graph
                        |                         |
              exact-source query          optional adapters
                        |
            prepare -> verify -> approve -> apply
                        |
                 durable journal / recovery
```

The default pipeline performs no model calls and does not execute indexed source. External provider and verification processes are opt-in trusted actions, not extensions of source-file authority.

| Directory | Responsibility |
|---|---|
| `src/core` | Paths, saved-file capture, content hashes, UTF-8 positions, deadlines, response budgets and spend ledger |
| `src/store` | SQLite WAL, FTS5, immutable blobs, graphs, artifacts, plans, journals, memories and vectors |

| `src/adapters` | Strict upstream graph contracts, LSP framing, Serena MCP and explicitly trusted provider bridges |
| `src/changes` | Patch preparation, permissions, conditional writes, verification and crash recovery |
| `src/protocol` | Eight-tool schema validation, stdio MCP and read-only authenticated loopback HTTP |
| `workers` | Independently written language/process bridges and static explorer assets |

## ADR 001 — Capability fusion, not application concatenation

The specification proposed Graft for structural orientation, Serena/SolidLSP for semantic operations and Graphify for broader relationships. This implementation retains that capability split but uses a native TypeScript compiler and standard-library AST workers by default. It does **not** launch three applications for every question. This makes a runnable local path possible without upstream installs, API keys or copying GPL application code. Optional adapters import additional evidence rather than overwriting all native facts.

Tradeoff: this is not complete upstream feature parity. SolidLSP is not bundled; the included LSP client is independently implemented. All-language semantics, the newer Serena REPL and Graphify's cloud/media features remain outside the shipped scope.

## ADR 002 — The graph is a snapshot-bound index, not source truth

Source bytes are content-addressed with SHA-256. A snapshot records paths, hashes, modes, omissions, workspace identity and analysis configuration. `Entity` IDs are snapshot-scoped; moving/renaming a symbol does not pretend to preserve a proven global identity.

Each directed `Observation` has a relation, resolution, producer and evidence IDs. `Evidence` records the source hash, byte and line ranges, and anchor granularity. Parallel relationships survive. An unresolved target remains null with its target label; a search-result sequence is never converted into a path.

Resolution categories: syntactic, exact binding, possible dispatch, heuristic, inferred concept, observed execution, authored contract and unresolved. These are not calibrated numeric confidence probabilities.

Graphify imports preserve `_src`/`_tgt` direction markers and raw arc order even when a persisted graph is marked undirected. Raw extraction is preferred; relations already removed by an upstream projection cannot be reconstructed. Graft's symbol-level edge evidence is recorded as an enclosing-symbol anchor, not a fabricated precise call site.

## ADR 003 — Explicit freshness

Capture enumerates saved files, reads/hash-checks contents and repeats file-set/stat checks. Stable deletions, creations, ordinary concurrent changes and ignored files are handled explicitly. A new graph is published only after successful capture and bounded analysis. Immutable snapshot queries remain valid after later disk changes.

This is a stable double scan, not an OS-atomic snapshot against a hostile writer. Unsaved buffers are unknown. Fresh captures remain O(source bytes); the in-memory/cached explicit-snapshot query path is faster. Parse caches are keyed by content/provider/version; project-level resolution is recomputed for each new graph, including unchanged consumers after dependency/export changes.

Workspaces have separate state and randomly initialized identities. Identical bytes can be reused within their CAS. This is not a federated multi-repository database or multi-machine synchronization system. SQLite WAL permits concurrent readers but serializes writers; do not put the live database on a network share.

## ADR 004 — Permission outside repository text

Repository JSON can tune limits and describe verification profiles. It cannot authorize profile execution, workspace writes or a custom interpreter. Those capabilities come from trusted host options. MCP schemas reject undeclared permission fields.

Approval records are local workflow gates, not a privilege boundary against an agent already able to run arbitrary host shell commands or edit the state database. Secure agent deployment still needs host/container permissions.

## ADR 005 — Reviewable changes, honest atomicity

Prepare validates expected hashes, byte boundaries and non-overlapping edits, produces a full unified diff and a derived immutable snapshot. Compiler renames are available for native TS/JS symbols. Isolated apply materializes a copied tree; it does not mutate the original workspace.

Workspace apply requires host permission, exact plan approval, successful bounded verification unless explicitly overridden, current base snapshot and a writer lease. Durable intent records and per-file before/after hashes support recovery. Rollback only restores bytes still matching this transaction's output, preserving concurrent foreign edits. The full multi-file update is not atomically visible to external readers. The copied tree is not an OS sandbox or a Git worktree.

## ADR 006 — Bounded retrieval and usage

Eight tools limit schema clutter. Read-only plans compose find/filter/references/read/select/group/limit without executing a generated program. One request deadline is shared; synchronous compiler calls are checked cooperatively and cannot always be preempted mid-call.

Result packing preserves whole records and evidence links. Complete overflow results are local immutable artifacts. Byte counts describe the structured envelope; token counts are explicitly estimated. No upstream savings percentage is repeated as a measured result.

The spend ledger reserves costs before calls, distinguishes sent from unsent attempts, keeps unknown settlement reserved, and prevents duplicate settlement. The native engine spends no model tokens. Full agent-harness usage requires the harness to report it and is not fabricated by the core.

## ADR 007 — Optional enrichment remains evidence-scoped

Memories distinguish confirmed findings, hypotheses, dead ends and superseded records. Current-file hashes determine staleness. Imported vectors carry model/dimension/hash identity; there is no built-in embedding model. LCOV is aggregate coverage, not a precise per-test map. Runtime imports prove only the supplied run's observations. SARIF findings are external analyzer data, not automatically security proofs.

Graph analytics include degree, weak components, import cycles and snapshot differences. Weak components are not Leiden communities. Framework hints are syntax-derived candidates and can be incomplete. There is no general taint analysis or formal correctness verifier.

## ADR 008 — Compilation context is part of a fact

`typescript-host.ts` owns an immutable filesystem and a bounded graph of configured projects. `TypeScriptProject` orchestrates one language service/program per configuration and merges source entities without flattening context-specific observations or diagnostics. Config roots and inherited relative paths are delegated to the pinned compiler. Source-reference navigation uses a tested compiler-host redirect, not generated build output. Same-source conflicting rename bindings fail closed.

No compiler host fallback reads arbitrary live disk files: only immutable captured source and trusted pinned standard-library files are readable. Files not covered by any configured program remain searchable but explicitly lack semantic coverage. The default trace can be a union of configurations; request `analysisContexts` to restrict it.

## ADR 009 — External protocol results are not automatic source authority

LSP parsing validates per-message limits, UTF-8 JSON, JSON-RPC result/error shape, negotiated UTF-16 positions, URI scope, LocationLinks, edit versions and overlaps. Unsupported callbacks receive MethodNotFound and workspace/applyEdit is refused. Read results are locally source-bound, not upstream correctness/coverage attestations.

The host-authorized `runLsp`/CLI operation materializes a snapshot, shares one deadline, invokes the provider, requests shutdown, verifies copied source hashes and returns bounded locations or a persisted change plan. Original source is never implicitly edited. Unknown external billing/network activity is reported; a copied tree is not an OS security boundary. No arbitrary repository-declared server command is auto-started.

## 0.3 extensions

`EditorBuffers` derives versioned overlays from strict disk snapshots; `serveEditor` and the VS Code client pass only explicit local read privileges. Federation signs immutable source envelopes and stores remote snapshots separately; it never transfers a live WAL database or grants remote source writes.

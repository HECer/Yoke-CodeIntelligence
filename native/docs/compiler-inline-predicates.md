# Predicate and assertion body contexts

The explicit host-selected TypeScript 5.8.3 classic body route additionally
handles predicate and assertion signatures in its admitted initializer, return,
expression-statement and direct complete-call if/switch/throw head contexts.
Direct if conditions retain the same checked relay for caller narrowing; no
argument effects are repeated. The original AST field and full replacement are
independently reconstructed. Loop tests and compound/short-circuit/nested
conditions remain outside this finite scope. See the
[statement-head qualification](../../docs/validation/integration-2026-10-23/inline-statement-heads/README.md).

This is the native body-expansion action,
not a claim about a TypeScript built-in refactor or every upstream inline form.
The original compiler registration, source capture, verification, approval,
write eligibility and conditional recovery gates remain mandatory.

An annotation such as `value is string` or `asserts value is string` is not a
value type. Native reconstruction derives its target and kind from the original
syntax. A complete original function signature/body copy stays under the fixed
false void guard. Its defaults and body never execute. A fixed runtime relay
returns the already computed result through that source signature. Its ordinary
rest parameter is unused; it does not call the source function again. Boolean
and void storage use fixed keywords. No provider-authored type expression is
inserted and no ambient type helper is trusted.

The compiler can also identify an inferred TypeScript predicate, such as an
unannotated `return typeof value === 'string'`. Its bounded parameter index is
checked against the actual source parameters; the existing primitive boolean
witness and original inert signature supply the relay type. The native checker
still compares the complete original/surviving binding and declaration-type
observations. Compiler inference remains evidence from the trusted host compiler,
not an independently proven or signed semantic attestation.

Every original argument is evaluated before parameter initialization, as in the
existing body route. The relay does not repeat calls, getters, computed members,
defaults or rest iteration. For a predicate target that is a simple identifier
or parenthesized identifier, a separate generated type-flow reference reads the
current caller binding. Native admission requires a single captured ordinary
lexical variable/parameter target. Ambient, exported, namespace, library/global
and imported bindings cannot gain this repeatable-reference privilege. Separately
authored export specifiers are matched by original declaration identity, including
aliases; a same-name caller parameter retains its own distinct identity. The relay
ignores the value of that reference: it returns the computed source result.
Other argument positions use fixed inert placeholders, not copied source effects.

This preserves caller narrowing, including constant boolean aliases and assertion
statements, when the original/expanded compiler observations agree. A property
access that needs escaping predicate flow still refuses if that flow cannot be
retained without repeating its effects. For inferred predicates with an unsafe
identifier target, the previous boolean recipe remains available only when its
unchanged diagnostic/binding/type checks succeed. It never suppresses a failed
caller-flow check or fabricates a completed empty result.

With `noUncheckedIndexedAccess`, a fresh rest collector's known present argument
positions retain their original tuple element types through fixed indexed
`typeof` syntax. There are no spread arguments, holes or source-controlled
getters in this fresh dense array. This removes only the compiler's additional
unchecked-access uncertainty; an element type that includes `undefined` keeps it.
JavaScript uses the corresponding fixed JSDoc type expression. The ordinary
recipe stays byte-for-byte unchanged when this compiler option is absent.

The optional frame metadata adds three fresh relay names, an inferred parameter
index when applicable and a dense-argument flag when required. Missing fields
retain the previous recipes. The same 128-frame/64-argument/64-parameter,
4 MB output, original-copy, observation and deadline bounds apply. Native rejects
coherent changed output/hash proposals that activate the inert signature, alter
the relay or replace source-derived targets. Source and snapshots remain immutable
during preparation; only explicitly owned test literals are executed by runtime
oracles.

The scoped guard passes146 distinct Rust functions/2 existing ignored, including
ten new-target integrations and nineteen body units. Format/all-target Clippy,
fresh primary library/CLI build, typecheck and TypeScript260/3 existing skips
pass; all1002 validated inputs match primary byte-exactly. Each actual binary
passes four owned CLI verification/approval/apply/conditional-recovery scenarios
and before/after literal runtime comparisons. See the
[indexed evidence](../../docs/validation/integration-2026-10-21/function-body-predicates/README.md).
JSDoc predicates, generics,
invocation-bound `this`, wider expression sequencing, all predicate target forms,
runtime/upstream equivalence and full R1/R1-R9 acceptance remain separate gates.
The existing body result remains `complete=false`.

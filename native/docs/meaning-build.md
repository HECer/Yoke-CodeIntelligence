# Source-bound model meaning builds

Meaning extraction is an explicit trusted-host operation. Default indexing and queries never start a model. Every accepted claim remains `inferred_concept`; `providerAttestation: unverified` distinguishes checked source citations from interpretation correctness. Local fixture tests establish protocol and persistence behavior, not model quality or remote billing correctness.

The host selects complete file or symbol-body units and optional fixed context groups. A body includes its captured implementation, not only its signature. Units over 16,384 UTF-8 bytes fail admission; selection is never silently shortened. Each context group contains at most sixteen selected units. Unit IDs bind the workspace, path, whole-file hash, absolute byte range and exact submitted bytes. Fixed packets are prepared before the first send; no adaptive reduce call changes the admitted job.

The complete request set, exact snapshot and canonical graph, source access policy, packet limits, all cache origins, and worst-case serialized graph capacity are checked before dispatch. Admission charges each packet for its bounded input, fragment and materialized result. A host graph budget is capped at 64 MB. A selection that exceeds it fails before any worker starts. Accepted coverage describes only the submitted units and fixed context groups. It does not establish exhaustive semantic coverage or relationship absence.

The parent reserves all cache misses in one transaction that also registers the job. Each child consumes one single-use reservation. A fully bound response's reported usage and bill are persisted before semantic validation or exit-code rejection. Sent attempts with unknown billing keep their reservation. Only durably never-sent attempts are canceled. An all-cache-hit job performs zero provider calls and creates zero accounting attempts. Failures are diagnostic states; neither status nor load retries or resumes work.

Cache keys include exact submitted bytes and whole-file hashes, ranges, packet context, extraction contract, model and version, provider fingerprint, billing currency, the snapshot's proven analyzer epoch and capture policy, and the host generation namespace. Currency isolation prevents totals from mixing receipts in different monetary units. Exact cache hits can be rebound to a newer snapshot only after source replay confirms the same bindings. Original source snapshots, request IDs, response artifacts, attempts and billing provenance remain explicit; reuse never fabricates a fresh provider receipt.

Successful response artifacts preserve the provider's typed fragment, including original local keys, ordering, aliases and duplicate claims. Graph normalization is derived from those original claims. Reuse also requires the original completed graph registration and its exact materialized packet in the registered graph artifact.

The provider fingerprint hashes the resolved executable, recognized script/configuration file arguments, and host-selected `provider_input_files`, with bounded streaming reads and the same operation deadline. Runtime environment, imported modules and unselected ambient configuration are not verified automatically. The host must select relevant supplemental files or change the extraction contract/generation when these dependencies change. Mutable output paths are not treated as input dependencies.

Responses and accounting may remain available after a failed build. Complete graph CAS bytes are staged before publication. One short SQLite transaction then registers the completed graph, all newly reusable cache pointers, the graph artifact registration and the completed job, with exact current-record preconditions. No transaction spans a provider process. An aborted publication leaves no newly discoverable complete graph or partial reusable cache.

Publication outcomes remain explicit when later status reporting fails: the returned error names the durably committed job and graph IDs, allowing inspection with a fresh deadline.

Read operations replay stored source, normalized claims, immutable response identity and durable ledger bindings without consulting an installed provider. Status compares dependencies against an explicitly selected snapshot and distinguishes current, changed and missing sources. `no_claims` records successful processing with no accepted claims. Queries retain packet provenance, relations, hyperedges, participant roles, support ranges and quotations. Aliases are display/search text and never imply concept identity.

Status distinguishes dispatched host attempts from confirmed bound responses. An incomplete build has `modelCallsThisRun: null`; internal provider calls remain unverified. Cost and usage totals refer to original receipts referenced by the graph, including cache origins, as declared by `accountingScope`. Separate current-run cost fields distinguish reuse from newly reported charges. A total remains null when any relevant report is unknown; explicitly named known sums and decimal totals preserve the available partial evidence without numeric overflow.

Typed retention validates original and rebound snapshots, response artifacts and accounting links. Missing or inconsistent dependencies fail closed. Originals remain immutable; refresh uses a different generation namespace.

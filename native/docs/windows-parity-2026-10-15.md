## Validation procedure and repairs

Each full native acceptance inventories Cargo targets and hashes all tracked
and nonignored source/control files before and after execution. Tests run in
bounded groups with two Cargo jobs and four test threads, retaining raw logs and
their hashes. Only ended Cargo integration-test executable/PDB outputs are
removed between groups to fit the Windows volume. Sources, dependency libraries
and evidence remain intact. Formatting, all-target Clippy with warnings denied,
Python packaging tests and TypeScript checks are separate gates.

The historical wave2 matrix records 196 integration targets and 97 library tests. A C:
attempt stopped after 417 passes and two OS112 fixture allocation failures when
the volume had about 54 MB free. D: supplied space and actual DOS aliases, but two
security fixtures could not set their required group/low-integrity metadata
there. All integration and documentation groups passed on D: and retain their
original log hashes. The package retry ran 95 library tests on D:, then each of
the two exact ACL fixtures on C:; both passed. The accepted receipt proves the
registered library set and 95+1+1 coverage. No test assertion, source behavior or
OS policy was relaxed. Original failures remain failed evidence.

The earlier first-wave frozen run passed 1,066 tests, failed four and ignored 25;
all 572 inventoried files were unchanged. That result is a failed baseline.
It exposed source-acquisition selection incorrectly requiring an extraction
proof for a scope-only derived snapshot. New tests distinguish arbitrary
derived IDs, derived/overlay analyzer 9 over disk analyzer 8, Git receipts and
invalid capture lineage.

Two failures required actual Windows 8.3 aliases, unavailable on the selected
G: test volume. The unchanged 15-test ignored-capture target passed on the
verified C: scratch volume with actual short names. No OS setting or production
path restriction was relaxed. Scratch roots outside the user's home also avoid
ambient ancestor ignore rules without changing production ignore policy.

The remaining failure was a marker-only runtime startup fixture whose 500 ms
session lifetime can legitimately expire before Python starts. The unchanged
case passed in isolation. The fixture now observes both HTTP completion and
startup; a separate test requires a live process and checks expiry against the
original admitted lifetime. Process exit must be observed before server shutdown
so shutdown cannot conceal a failed expiry cancellation. Production timeouts
remain unchanged.

Independent reviewers cover View budgets/evidence, decision privacy/retention,
capture lineage and HTTP fixture assertions. Synthetic protocol fixtures do not
certify all real servers or hosted services. This wave makes no new external
model calls, public deployment, upstream performance comparison or universal
correctness claim.



Wave4 process lifecycle repair installs child/stdio cleanup before post-spawn deadline/cancellation rejection and retains actual spawn-failure checks. The held-parent metadata/journal reader has per-operation scoped security and refusal proof; the existing one-case 16-root recovery test passes under its unchanged30-second deadline.

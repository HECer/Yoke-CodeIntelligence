# Derived source graphs and registered collections

The independent Rust manifest, configuration and Markdown extractors produce immutable overlays rather than changing source snapshots or canonical structural observations. Each overlay binds the workspace, snapshot and canonical graph hash. A `native_derived_source_graph_v1` record roots its content-addressed JSON artifact. Extraction never launches commands found in manifests, starts an MCP server, fetches a link, reads an environment value or grants permissions.

Evidence precision is explicit. `unique_literal_occurrence` means the decoded declaration label occurs once in the captured source; its exact UTF-8 byte range is corroborated against those bytes. Repeated or decoded labels that cannot be located unambiguously use `file` evidence. This is enclosing-file provenance, not an invented parser token range. Markdown relationships retain the exact authored link or citation range. Source hashes and immutable canonical graphs are checked before publication.

`manifest_graph::extract` reads npm JSON, APM YAML, Cargo TOML, Python pyproject TOML, Go module declarations and Maven XML. Dependency aliases remain distinct from package names. Cargo inherited aliases use the nearest declared workspace dependency table; path links require a matching declared target package name. Uncaptured/external dependencies remain explicit declarations. XML DTDs are rejected. Script bodies and dependency URLs are not copied into graph metadata.

`config_graph::extract` emits JSON/TOML/YAML/XML key paths and authored reference candidates. Local JSON pointers can link declared keys. Duplicate JSON fields are refused. Streaming YAML preflight counts expanded aliases and collection depth before materialization: 20,000 expanded nodes and depth 64 are explicit bounds; recursive/unresolved aliases fail. MCP descriptions expose server names, safe command names, selected npx/bunx/uvx package declarations and environment variable names. Environment values and arbitrary argument strings are excluded. These descriptions never become host launch configuration. .NET project/solution XML, legacy solution records, Delphi/Lazarus form components and BYOND text descriptor asset references have independently labeled structural observations; binary icon assets need explicit media ingestion.

Configuration paths separate components with dots. Literal key characters `~`, `.`, `[` and `]` are escaped as `~0`, `~1`, `~2` and `~3`; array indices remain structural brackets. A literal key `a.b` therefore cannot collapse into nested keys `a` / `b`. JSON pointer components are decoded and converted to that same escaped component representation.

`markdown_graph::extract` uses the pinned CommonMark parser with source offsets for inline/reference/wiki document links, metadata blocks and qualified code-span symbol citations. Percent-encoded UTF-8 local targets are decoded and scoped. A uniquely matching symbol name is a candidate, not a compiler-certified reference. External links remain authored targets and are never fetched implicitly. Fenced and indented code are excluded from authored link extraction. Reference definitions and indented blocks follow CommonMark grammar, including paragraph-boundary rules.

`graph_collections::Registry::open` requires an existing absolute host-selected directory. Its SQLite registry stores validated immutable snapshot/graph registrations and a standalone hash-verified source archive under restricted names. Each registration copies at most 64 MB of captured UTF-8 source transactionally. Only host code may register projects. Replacing a registration selects a new immutable graph; previously returned views keep their original identities. Removal checks the expected registration ID. Joining rejects absent, duplicate and identical workspace/snapshot scopes, preserves direction and every parallel observation, and namespaces entity IDs, internal keys, parent keys and evidence with their source workspace/snapshot. Lineage is explicit. Same-kind/name type matches across workspaces are separate heuristic candidates; they never merge entities or claim type identity. No external registry entry implicitly pins an original source store.

`Registry::query` accepts strict `find`, `trace` and `read` requests over selected registered names. Find prefers exact names, otherwise searching qualified names and signatures. Trace uses the canonical Rust directed traversal with namespaced IDs and retains original source evidence. Read resolves one namespaced entity exclusively through the registry's immutable source archive, checks SHA-256 and UTF-8 byte boundaries, and returns up to 256 KB. Historical read remains valid after original-project source changes, original snapshot retirement and original-store blob quarantine/purge. It never accepts caller-selected filesystem roots.

Bounded operations fail explicitly on capacity or deadline exhaustion. These APIs do not claim exhaustive semantic or runtime coverage. Final CLI/MCP integration, end-to-end tests and upstream acceptance coverage are tracked separately from library implementation.

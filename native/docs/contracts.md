# Native contract extraction

The independent Rust extractor reads immutable captured UTF-8 source. It never imports project modules, starts a model, follows schema URLs, or connects to a database. `native/tests/contracts.rs` exercises actual engine indexing and graph assembly, not an external analyzer fixture.

| Input | Native extraction | Evidence and limits |
|---|---|---|
| SQL | `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`, `INSERT INTO`, `FROM`, `JOIN`, `UPDATE` | Token-bounded statement/table anchors; comments, SQL string literals and PostgreSQL dollar strings are skipped. Quoted identifiers retain exact source ranges. This is a bounded declaration/access extractor, not a dialect parser, CTE resolver or database binder. |
| Prisma | `model`, `enum`, `type`, model/type fields, `@@map` model table mapping | Declaration and field anchors preserve original bytes. Field signatures retain attributes such as `@map` and `@relation`; they do not imply database constraints have been independently verified. |
| GraphQL | `type`, `input`, `enum`, `interface`, `scalar`, `union`, object/input/interface fields | Comments and description strings cannot create declarations. Field argument lists are skipped when finding the return type. Directive interpretation, extensions, external schemas and compatibility checks remain outside extraction. |
| Protobuf | Top-level `message`, `service`, `enum` headers | Exact header through the opening brace; fields, nested messages, RPC binding and wire compatibility are not claimed. |
| OpenAPI JSON / Swagger JSON | Literal path/method operation declarations | The exact method key through its operation object is anchored; an unrelated earlier copy of the path string cannot move the evidence. Malformed JSON, duplicate object keys and malformed path/operation object shapes produce diagnostics. External `$ref` values are not resolved. |
| JSON Schema | Top-level property declarations when `$schema` exists | Property key and its object/value are anchored. This is extraction, not JSON Schema validation. |
| JavaScript / TypeScript | Literal `fetch`, supported `axios.METHOD`, `app.METHOD` / `router.METHOD`, `prisma.MODEL.ACTION` / `db.MODEL.ACTION`, member event calls and `process.env.NAME` | Tree-sitter call/member nodes are used. Comment text and strings containing example code are not interpreted as calls. Dynamic arguments and interpolated template literals are skipped. A function named `fetch` or `prisma` is a syntax pattern, not proof of its library binding. |
| Python / Rust and compatible call ASTs | Literal `getenv`, `os.getenv`, `os.environ.get`, `environ.get`, `std::env::var`, `std::env::var_os`; Python literal `app` / `router` decorators | Environment names are indexed; generated entity signatures never contain an environment value. Exact source remains authoritative. Aliases and arbitrary language/framework conventions are not exhaustively supported. |

Strict JSON is required for OpenAPI and JSON Schema artifacts. Captured `tsconfig.json`, `jsconfig.json`, and their dotted variant filenames additionally support comments and trailing commas as JSONC. Masking preserves byte offsets. YAML OpenAPI remains searchable text in this module.

Candidate relationships include `possibly_accesses_table`, `possibly_implemented_by_migration`, `possibly_consumes_contract`, `possibly_implements_contract`, and `possible_event_delivery`. Even a unique match is labeled `heuristic`. Zero or multiple matches produce an unresolved observation with its original source evidence. The graph remains non-exhaustive.

Matching uses the nearest captured project manifest (`package.json`, `Cargo.toml`, `pyproject.toml`, `go.mod`, `pom.xml`, or a `.csproj`) and conservative `services/NAME`, `apps/NAME`, and `packages/NAME` directory scopes. A root manifest does not merge distinct directories in those layouts. Other layouts need future explicit host scope configuration; a scope or name match cannot establish service deployment, URL origin, database identity, event-bus identity or runtime execution. SQL/table-name case normalization is a candidate comparison, not dialect-specific identifier equality.

Contract entities expose their comparison domain in `qualifiedName`, such as `http:GET:/users`, `sql:users`, `orm:user`, `event:order.created`, or `env:API_URL`. Original names, source paths, signatures and exact byte ranges are separate fields. Source-scoped observations preserve parallel operations; graph assembly recomputes cross-file candidates after every new snapshot rather than retaining old bindings from an unchanged consumer.

Resource limits are explicit: at most 200,000 lexical schema tokens per file, 20,000 entities per contract extraction, 128 JSON nesting levels, 200 diagnostics per extraction, and the caller's shared deadline. Syntax diagnostics cover malformed JSON and missing schema bodies/comments/strings; they are not a complete SQL, Prisma, GraphQL or Protobuf compiler check.

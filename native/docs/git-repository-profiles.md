# Fixed-root Git capture in selected MCP profiles

```sh
yoke --root /absolute/project git repository-scope --capture --serve --allow-index-read --trust-git --profile session
# --profile native|session|serena|trail|graft|graphify
```

The absent profile and explicit `native` select the preceding eight-tool native
server. `session` uses the existing nine-tool session view; `serena`, `trail`,
`graft` and `graphify` use their existing 53/6/6/10-tool catalogs. Profile selection
requires explicit `--serve`, which requires `--capture`. It grants no Git trust,
root, runtime or source-write permission. Initial trusted capture completes before
protocol startup, without unsolicited summary JSON on stdout.

Every selected profile retains the same invocation-owned Git driver. Normal and
bounded retrieval indexing refresh actual Git/working-source evidence under its
fixed root/program/limits/follow/preference selection. Captured and current source
policies remain independent. Included crossed repositories stay read-only, also
for older writable snapshots. Ordinary unscoped serve/session defaults retain
their preceding source behavior, catalogs and saved session identities.

A versioned host binding hashes the canonical root, explicitly selected Git
program spelling, fixed options/limits and observed preference ID. Program
selectors must be UTF-8 and at most 16,384 bytes. This is a selected path binding,
not executable-byte attestation or an OS sandbox. Alias spellings conservatively
create different bindings. Project/snapshot/MCP JSON cannot create this driver.

Only when the driver is present, the session fingerprint replaces its dynamic
repository observation with that stable host binding. New captured file membership
does not invalidate an otherwise unchanged saved session. Changed program, limits,
follow choices or preference lifetime require a new host/session binding. The
existing session label/workspace IDs and all absent-driver fingerprints remain
unchanged. The CLI creates a fresh session label for each selected-profile server;
the trusted Rust API can explicitly resume a named session with the same binding.

Session admission rechecks exact persisted state and current preferences before
selected tool/state/note operations. Stale concurrent state, changed/cleared/new
preferences refuse; no note mutation or silent authority widening follows.
Restart explicitly with the current selection. Existing named-note permissions
remain those of the selected session adapter; notes remain distinct from project
source and host Git preferences. No shell, Python, model or debugger runtime is
started or authorized by profile selection.

This remains a fixed-root host. Registered projects and collections are rejected
before resolving their foreign roots when this driver is present. Model requests
cannot activate unregistered roots. Ordinary sessions without the driver retain
their existing registered-project/collection behavior. Explicit authenticated
[HTTP targets](git-repository-http.md) reuse the same driver per fixed principal.
Multiple registered projects within one Git target, further client behaviors and
full upstream/Windows/release acceptance remain open.

Actual native protocol calls qualify all five added profiles and their source
baseline; pinned Claude 2.1.306 connects to the Serena profile in owned private
configuration. That health check is not a model turn or interactive UI validation.
See the [base host](git-repository-host.md), [capture](git-repository-scope.md) and
[preferences](git-repository-preferences.md) contracts.

# Offline source graph explorer

HTML exports retain the entire canonical graph in inert JSON. Symbol results are paginated in groups of 100; search and kind, language and relation filters apply to all results. The canvas shows the current page plus a matching selection, with at most 5,000 directed observations; the relationship panel exposes every incident observation through pages of 40. Indexed adjacency and evidence maps avoid repeated whole-graph scans when selecting a symbol.

The canvas supports bounded deterministic force or radial layouts, zoom, pan, node dragging, fit/reset and keyboard selection. Parallel arcs and self loops retain separate observation identities. Layout positions carry no semantic meaning. Neighbor focus follows the selected relation filter. Community hulls appear only for the separate source-bound metadata generated by checked canonical analysis; ordinary graph-only HTML exports explicitly report that no community overlay is available. Communities remain heuristic.

In the original metadata-only mode, the details panel shows captured declaration headers and source paths, UTF-8 ranges, hashes, trust, producers and evidence identities. Full source file bytes are not embedded. Unresolved targets remain labels, not invented graph entities. The file has no network or live source access, and all captured text is rendered as text. Canonical JSON downloads preserve the original graph, independently of filtering and layout. PNG downloads describe the current canvas presentation.

`serialize_explorer` and `write_explorer` validate canonical source/graph authority and generate separate checked community metadata. The output writer rejects linked/reparse path components, uses create-only publication, and permits an existing destination only when a bounded exact comparison proves identical bytes. JSON and GraphML exports preserve canonical observations; every dynamic GraphML attribute is XML-escaped. Template markers inside source metadata remain literal data.

Rendering races each animation frame against a bounded one-shot timer, cancels the losing callback and completes at most once. This keeps layout and drawing responsive in embedded clients that expose animation-frame APIs without dispatching callbacks. Generation changes cancel stale layout work; PNG export remains disabled while layout or rendering is pending and captures the current canvas only after a final draw. Development scheduler checks execute the extracted pure scheduling function with the host Node runtime; the exported file itself requires only a browser.

If the timer wins a frame race, layout completes all remaining bounded steps in that callback and draws synchronously. Physics uses deterministic samples of at most 800 repulsion pairs and 256 springs for 48 steps; this affects positions only and does not delete canonical or displayed observations. Normal animation frames retain short iteration chunks. This prevents nested timer throttling from leaving an otherwise visible embedded client indefinitely in a computing state.

GraphML explicitly refuses source metadata characters that XML 1.0 cannot represent instead of publishing an invalid XML document or silently changing labels. JSON and HTML preserve those original values. XML escaping and XML character representability are checked separately.

## Explicit captured source export

`yoke --root /project export --format html-source --output /private/source.html`
selects a separate source-bearing presentation. Omitting `--snapshot` performs
the ordinary native capture; supplying it selects that immutable saved capture.
The default generated filename is `<snapshot>.source.html`. The original `html`
mode stays metadata-only and document graphs retain their distinct decoded/XML/
container presentation. `serialize(graph, "html-source")` alone is insufficient:
library callers use `serialize_source_explorer` or `write_source_explorer` with
the explicit Store, snapshot, graph, options and deadline.

Code shows the captured file, path/hash/snapshot and exact selected UTF-8 byte
range. Source pages contain at most120 lines; the whole original file is embedded,
including BOM, CRLF and Unicode. Outline pages contain at most80 original saved
entities from the selected file, ordered by byte range with original parent keys.
Selecting an entry opens its Code range. Context preserves the existing paged
directed/parallel incident observations, resolution, unavailable targets, original
evidence, coverage and omissions. Read exact quote opens an original observation
anchor. None of these views establishes compiler/runtime truth or invents omitted
declarations. Tabs support ArrowLeft/Right, Home and End; relation chips and the
original select stay synchronized.

`SourceExplorerOptions` has closed camelCase fields `maxSourceBytes` (default
16000000, hard maximum32000000) and `maxOutputBytes` (default64000000,
1024..128000000). The CLI uses these defaults. The existing checked graph bounds
also apply. The complete captured source set must fit before any blob opens;
serialization and escaping use bounded deadline-aware writers. Exceeding any
bound fails the whole export, without partial publication or replacing foreign
output. Source/graph/path-policy/hash/range checks precede source publication.

The file contains actual source and requires the same access controls as source
state. Values are inert JSON and DOM text; no project code is evaluated, no
provider starts, and the CSP disallows connections. Captured hashes and ranges
describe the export-time checked snapshot, not current disk freshness or a signed
portable attestation. Editing an HTML file invalidates its original provenance.
Live rebuild/reload requires a separate explicitly authorized workflow and is not
implemented by this static export.

records meaningful Unicode/hostile-text/source-integrity/budget/write/CLI checks,
actual legacy-byte preservation and three real browser development rounds.

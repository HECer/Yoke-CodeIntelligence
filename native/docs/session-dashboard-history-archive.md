# Global document history archive (under implementation)

No history-archive CLI, dashboard action or acceptance is claimed yet.

The host workflow must retire closed journals without removing recovery evidence
or allowing an old write selection or reviewed proposal to revive. It therefore
starts from an explicitly completed binding migration and its exact current
destination owner generation. The old and new complete selections, their two
independent write authorities and a separately selected private archive directory
remain host input. Project files and unfinished journals are ineligible.

A concrete plan must bind the completed migration, both journal-root identities,
current source/owner identity and security, each original canonical header/event,
its physical identity/security/bytes and an independently guarded archive root.
Every included journal must have a complete checked terminal chain and no
retained original backup or prepared output. Other targets and foreign entries
remain untouched. Empty or incomplete inspection cannot certify full recovery.

An immutable bounded archive must retain and verify every original canonical
record before its original is removed. Original file identities/security and
exact bytes remain deletion preconditions. A durable removal intent and fixed
per-target marker must block new writes and further binding migration before
removal begins. Archive publication uses no-replace creation. The operation
must never edit selected configuration bytes or owner metadata, reload a profile,
grant writes from serialized data or execute analyzed project content.

Explicit event-reviewed recovery must recognize only exact originals and their
admitted immutable archive. Cancellation can retain originals before removal
intent; after that intent, recovery only resumes the approved removal. It never
reconstructs missing originals or switches to a destructive opposite direction.
A lost response, foreign
occupant, changed bytes/identity/security, missing record or unavailable root
retains uncertainty and evidence. Completed markers and compact operation history
remain retained. Physical purge and standalone owner deletion are separate work.

Implementation requires adversarial path/Unicode/capacity/record-chain/authority,
interruption and recovery tests, followed by actual CLI validation. This contract
does not mark the existing STATUS requirement complete.
